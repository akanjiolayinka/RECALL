# Getting help

Recall is a small project maintained by one person, with help from
contributors. Here's where to go so your question finds the right people.

## Questions and ideas: Discussions

If you're not sure something is a bug, want to know how to do something,
or have an idea you'd like to talk through, start a thread in
[GitHub Discussions](https://github.com/akanjiolayinka/RECALL/discussions).
Setup trouble, "is this expected?" and feature ideas all belong there. Other
people can find the answer later, and a good idea can become an issue once
it's taken shape.

## Bugs: Issues

If something is clearly broken, [open an issue](https://github.com/akanjiolayinka/RECALL/issues/new/choose)
using the bug report form. A report we can act on usually has:

- what you did, step by step, and what you expected
- what happened instead, with the exact error message if there was one
- your OS and version, and how you got Recall (built from source at a
  certain commit, or a CI installer from a certain run)
- if it's about a particular file not being read or found, the file type and
  roughly how big it is

Please don't attach your own documents or screenshots that show their
contents. If a file is needed to reproduce the problem, try to make a small
made-up one that shows the same thing. `test-data/` has examples.

Before opening an issue, a quick search of existing issues saves everyone
time.

## Security problems

Don't report these in public. [SECURITY.md](SECURITY.md) explains how to
report them privately.

## What to expect

Answers come when the maintainer and contributors have time, so it may take
a few days. A clear question with the details above usually gets a faster
and better answer.
